# Yuna Clinic

เว็บจัดการคลินิกความงามภาษาไทย โทนขาว–ทอง รองรับบนเครื่องด้วย SQLite และบน Vercel ด้วย Flask + PostgreSQL

อ่าน [คู่มือ GitHub / Vercel](DEPLOY.md) สำหรับการตั้งค่าฐานข้อมูลและ Deploy ข้อมูลผู้รับบริการไม่รวมอยู่ใน repository

## เริ่มใช้งาน

1. แตกไฟล์ ZIP ก่อนใช้งาน แล้วเปิด `Start-Yuna-Clinic.cmd`
2. เปิดเบราว์เซอร์ที่ `http://127.0.0.1:8765` หากหน้าเว็บเปิดก่อนระบบพร้อม ให้กดรีเฟรช
3. ครั้งแรก สร้างบัญชี **Owner** และตั้งรหัสผ่านอย่างน้อย 12 ตัวอักษร
4. เพิ่มบัญชีทีมงานที่หน้า **ผู้ใช้งาน & สิทธิ์** แล้วเลือกบทบาท
5. เปิดหน้าต่างโปรแกรมค้างไว้ขณะใช้งาน ปิดระบบด้วย Ctrl+C

ต้องมี Python 3.10 ขึ้นไป ตัวเปิดเว็บจะใช้ Python ที่มีอยู่กับ Codex ในเครื่องนี้ก่อน ไม่ต้องติดตั้งไลบรารีเพิ่มเติม หากใช้อีกเครื่อง ให้ติดตั้ง Python ก่อน

สามารถเริ่มระบบด้วย `python server.py` ได้เช่นกัน อย่าเปิดระบบซ้ำสองชุดบนพอร์ตเดียวกัน

## ส่วนที่ใช้งานได้

- **เวชระเบียน:** ค้นหาชื่อ/HN/โทรศัพท์ เพิ่มผู้รับบริการ ทบทวนประวัติแพ้ยา โรคประจำตัว ยาที่รับประทาน ที่อยู่ และผู้ติดต่อฉุกเฉิน
- **Consent:** บันทึกการยินยอมและถอนความยินยอม แยกการรักษากับภาพก่อน–หลัง พร้อมชื่อผู้ลงนามและเลขเวอร์ชันเอกสาร
- **ภาพก่อน–หลัง:** อัปโหลด JPG/PNG ไม่เกิน 2.5 MB ต่อภาพ เก็บในฐานข้อมูลหลังระบบเข้าสู่ระบบ
- **นัดหมาย:** กำหนดแพทย์ ห้อง วันเวลา และระยะเวลา ป้องกันนัดทับซ้อนของแพทย์ ห้อง และผู้รับบริการ เปลี่ยนสถานะคิว บันทึกวันและผลติดตาม
- **หัตถการ:** ตรวจว่าทบทวนประวัติและมี Consent แล้ว บันทึกแพทย์ ผู้ช่วย รายละเอียด ผลิตภัณฑ์ และจำนวน พร้อมตัด Lot ตาม FEFO ในธุรกรรมเดียวกัน
- **คอร์สและสมาชิก:** เพิ่มคอร์ส ใช้สิทธิ์ ป้องกันยอดติดลบ/คอร์สหมดอายุ ดูประวัติใช้คอร์ส เปลี่ยนระดับสมาชิก และเก็บรายละเอียดโปรโมชั่น
- **คลัง:** เพิ่มสินค้า รับเข้า Lot จัดสรรยอดตั้งต้น ระบุวันหมดอายุ/ต้นทุน ปรับสินค้าออกพร้อมเหตุผล แสดงสินค้าใกล้หมดและ Lot ใกล้หมดอายุ
- **การเงิน:** สร้างใบเสนอราคา ใบเสร็จ รายจ่าย รับชำระจากใบเสนอราคาได้ครั้งเดียว พิมพ์/บันทึก PDF ผ่านเบราว์เซอร์ และส่งออก CSV ตามตัวกรอง
- **ค่ามือและคอมมิชชัน:** บันทึกยอดต่อหัตถการ และสรุปรายบุคคลตามเดือน
- **Dashboard:** สรุปรายรับ ผู้รับบริการ นัดหมาย สินค้าใกล้หมด กราฟรายเดือน และบริการที่มีรายรับสูงสุด
- **ผู้ใช้:** สร้างบัญชีตามบทบาท เปิด/ปิดบัญชี ตั้งรหัสผ่านใหม่ และยุติเซสชันเดิมเมื่อปิดบัญชีหรือเปลี่ยนรหัสผ่าน
- **Audit:** ดูประวัติการเข้าสู่ระบบ เปิดเวชระเบียน/ภาพ และเปลี่ยนข้อมูล ไม่มีการแก้ไขหรือลบ Audit ผ่านหน้าเว็บ

## สิทธิ์

| บทบาท | ขอบเขต |
|---|---|
| Owner | ทุกส่วน รวมบัญชีผู้ใช้ Audit และหน้า PDPA |
| แพทย์ | เวชระเบียน Consent ภาพ นัดหมาย หัตถการ และดูคลัง |
| พยาบาล | เวชระเบียน Consent ภาพ นัดหมาย หัตถการ และดูคลัง |
| Front | ข้อมูลติดต่อ/สมาชิก นัดหมาย คอร์ส โปรโมชั่น ใบเสนอราคา และใบเสร็จ ไม่เห็นประวัติสุขภาพ/ภาพ/กำไร |
| คลัง | สินค้า Lot รับเข้า ปรับออก และความเคลื่อนไหว |
| บัญชี | การเงิน รายจ่าย สรุปยอด และค่ามือ/คอมมิชชัน เห็นชื่อ/HN เพื่ออ้างอิงเอกสาร แต่ไม่เห็นเวชระเบียน |

ทุกสิทธิ์ตรวจที่ระบบหลังบ้าน ไม่ใช่เพียงซ่อนเมนู โดยแพทย์และพยาบาลมีสิทธิ์บันทึกหัตถการเท่ากันในเวอร์ชันนี้

## ข้อมูลตัวอย่างที่นำเข้า

ข้อมูลที่นำเข้าบนเครื่องเก็บแยกจาก Git โดยไม่รวมฐานข้อมูล ไฟล์ Excel ภาพผู้รับบริการ และรายงานการนำเข้าใน repository รายละเอียดการนำเข้าของเครื่องต้นทางอยู่ใน `IMPORT-NOTES.json` ซึ่งถูกกันออกจาก Git

เมื่อ clone repository ไปยังเครื่องใหม่ ระบบจะสร้างฐานข้อมูลว่างเมื่อเปิดครั้งแรก จากนั้นสร้างบัญชี Owner และเพิ่มข้อมูลได้ ข้อมูลจากเครื่องต้นทางจะไม่ติดไปกับโค้ดโดยอัตโนมัติ

ปรับวันที่ พ.ศ. เป็น ค.ศ. สำหรับจัดเก็บ และแสดงวันที่ภาษาไทยในหน้าเว็บ ไม่นำเข้าเลขบัตรประชาชน ไม่ตีความช่องสุขภาพที่ว่างว่า “ไม่มี” ไม่มีการสร้างนัดหมาย หัตถการ Consent หรือภาพขึ้นเองจากรายการรายรับ

พบยอดตั้งต้นติดลบ 4 รายการ คงค่าเดิมไว้โดยไม่แก้ข้อมูลต้นฉบับ สามารถใช้ปุ่ม **แก้ยอดตั้งต้น** หลังตรวจนับ พร้อมระบุเหตุผลที่เก็บใน Audit log

ยอดจาก `inventory` เป็นยอดตั้งต้นที่ยังไม่มี Lot จึงต้องเข้า **รับสินค้า / ระบุ Lot** และติ๊ก **จัดสรรจากยอดตั้งต้น** ก่อนเบิกหัตถการ การจัดสรรจะไม่เพิ่มยอดรวมซ้ำ ประวัติ stock in/out ไม่ถูกนำมาตัดยอดตั้งต้นซ้ำ

ช่อง `Unit price` ในประวัติ stock in/out เป็นหน่วยสินค้า จึงไม่นำมาคำนวณต้นทุน แบบฟอร์ม stock in form/out form ไม่เชื่อมเป็นธุรกรรม เนื่องจาก Receipt No. ในรายการจำนวนมากว่าง รายละเอียดการนำเข้าอยู่ใน `IMPORT-NOTES.json`

## ขอบเขตและสิ่งที่ต้องตั้งค่าก่อนใช้งานจริง

- โหมดบนเครื่องใช้ SQLite ส่วนโหมด Vercel ใช้ PostgreSQL ร่วมกันระหว่าง worker พร้อมตรวจสิทธิ์ที่ API ทุกคำขอ ต้องเชื่อมฐานข้อมูลและตั้ง Environment Variables ก่อนใช้งาน
- หน้าเว็บใช้ HTML/CSS/JavaScript ปกติ ระบบหลังบ้าน Python และ SQLite จัดการบัญชี สิทธิ์ และการบันทึกข้อมูล การเปิด `index.html` โดยตรงจะใช้งานไม่ได้ ต้องเปิดผ่านตัวรัน
- Consent เป็นข้อมูลอ้างอิงเอกสาร ไม่ใช่ลายเซ็นอิเล็กทรอนิกส์ ควรเก็บเอกสารลงนามต้นฉบับ และประเมินขอบเขต Consent ต่อหัตถการให้เหมาะสม
- กำหนดชื่อแพทย์ให้ใช้ชื่อเดียวกันเสมอ เพราะการตรวจตารางแพทย์ใช้ชื่อที่กรอก เวอร์ชันนี้มีห้อง 1–3 และห้องปรึกษา ไม่มีระบบจัดตารางกะ/วันหยุดแพทย์
- โปรโมชั่นเป็นทะเบียนเงื่อนไข ยังไม่หักส่วนลด/ภาษีอัตโนมัติในเอกสาร ให้กรอกยอดสุทธิที่ตรวจสอบแล้ว
- การเพิ่มคอร์สและหัตถการไม่สร้างรายรับอัตโนมัติ เพื่อไม่ซ้ำกับรายการนำเข้า ต้องออกใบเสร็จหรืออ้างอิงรายรับเดิมเอง
- การเงินใช้เอกสารแบบยอดรวมต่อรายการ ไม่ใช่ระบบบัญชีเต็มรูปแบบ ไม่มีใบกำกับภาษี ระบบคืนเงิน หรือตารางภาษี
- สรุปกำไรแยก **กำไรตามไฟล์ต้นฉบับ** กับ **ส่วนต่างรายรับ–รายจ่าย** ยังไม่ใช่กำไรสุทธิครบต้นทุน ค่ามือและคอมมิชชันเป็นยอดที่บันทึกต่อครั้ง ไม่ใช่สูตรค่าตอบแทนอัตโนมัติหรือหลักฐานจ่ายเงิน
- การแจ้งเตือนอยู่ในหน้าเว็บ ยังไม่ส่ง LINE/SMS/อีเมลอัตโนมัติ
- บัญชีใช้รหัสผ่านแบบ PBKDF2 และเซสชันฝั่งเซิร์ฟเวอร์ หมดอายุเมื่อไม่มีคำขอ 30 นาที/ครบ 8 ชั่วโมง บัญชี Owner ที่ลืมรหัสผ่านและไม่มี Owner คนอื่นต้องให้ผู้ดูแลระบบกู้คืนจากฐานข้อมูล
- ข้อมูลเก็บใน `data/clinic.db` ยังไม่มีการเข้ารหัสไฟล์ฐานข้อมูลหรือระบบสำรองอัตโนมัติ Audit ป้องกันการแก้ผ่านเว็บ แต่ผู้ที่มีสิทธิ์เขียนไฟล์ฐานข้อมูลยังแก้ไขได้
- เครื่องมือ PDPA ไม่ใช่การรับรองความสอดคล้องทางกฎหมาย ต้องจัดทำนโยบาย ระยะเวลาเก็บ ช่องทางขอใช้สิทธิ์ การลบ/สำรองข้อมูล และผู้รับผิดชอบก่อนใช้งานจริง
- โหมด Vercel รองรับ HTTPS, Secure Cookie, Origin และรหัสตั้งค่า Owner ครั้งแรก คลินิกยังต้องกำหนดการสำรอง/กู้คืน นโยบายข้อมูล และตรวจสอบความปลอดภัยก่อนใช้จริง ตัวรันบนเครื่องยังผูกเฉพาะ `127.0.0.1`

## สำรองข้อมูล

ปิดระบบก่อน แล้วคัดลอกโฟลเดอร์ `data` ทั้งโฟลเดอร์ไปยังพื้นที่สำรองที่จำกัดสิทธิ์ เก็บรหัสผ่าน Owner ให้ปลอดภัย ชุด ZIP นี้มีข้อมูลผู้รับบริการจากไฟล์ที่แนบ จึงควรเก็บในพื้นที่ของคลินิก

## ผลตรวจสอบ

ทดสอบด้วยฐานข้อมูลสำเนา ไม่เพิ่มบัญชีทดสอบลงในไฟล์ส่งมอบ ผ่านการตรวจ API หลัก 47 รายการ รวมสิทธิ์ครบทุกบทบาท เซสชัน CSRF FEFO การย้อนกลับธุรกรรม นัดทับซ้อน การใช้คอร์ส Consent การแก้ยอดตั้งต้นพร้อม Audit และการออกใบเสร็จซ้ำ นอกจากนี้ตรวจการสร้างหน้าจอ/แท็บ 21 รูปแบบด้วย JavaScript และตรวจสถานะข้อมูลว่าง ไม่ได้ทดสอบภาพหน้าจอหรือคลิกผ่านเบราว์เซอร์จริง

## โครงสร้างไฟล์

`public/index.html`, `public/styles.css`, `public/app.js` คือหน้าเว็บและโค้ดส่วนติดต่อผู้ใช้

`server.py` คือระบบหลังบ้าน, `schema.sql` คือโครงสร้างฐานข้อมูล, `data/clinic.db` คือข้อมูลที่นำเข้าและข้อมูลที่บันทึกใหม่
